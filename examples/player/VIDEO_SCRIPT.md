**口播**

> 这期视频，我们来完整复盘这台 ESP32-S3 无损音乐播放器的制作过程：它是怎么从一块飞线密密麻麻的洞洞板原型，一步步变成 4 层 PCB，并最终完成播放和音频测试的。

> 不过在开始之前，先回答一个最基本的问题：现在手机这么强，为什么还要自己折腾一个随身音乐播放器？

> 现在的手机，性能越来越强，拍照越来越好，游戏甚至能跑到一百多帧。但有一个东西，好像慢慢被厂商放到次要位置了——音乐。

> 当然，现在的蓝牙耳机非常方便，音质也已经比以前好了很多。但如果你真正想折腾高码率甚至无损音乐、不同 DAC、耳放、耳机阻抗、底噪和失真这些东西，有线耳机依然有几个很实际的优势：简单、稳定、成熟，而且便宜。一副成熟的有线耳机，加上一颗价格不高的 DAC，就能组成一套可靠、可重复测试，也方便继续折腾的音频系统。

> 所以这一次，我不打算买一台昂贵的 Hi-Fi 播放器。我们自己做一个。

> 用 ESP32-S3 做主控，加上 DAC、屏幕和 SD 卡，做一台真正属于自己的无损随身音乐播放器。而且最后，我们不靠“听起来更通透”这种玄学评价。直接用专业声卡把输出录回来，看频响、底噪和失真，再把三款声卡和 Xperia 5 V 放在一起做一次 ABX 盲听。看看这个自己做出来的小东西，到底能不能打。

**屏幕大字**

`三款声卡 + Xperia 5 V｜测量 + ABX 盲听`

## 01:18–02:24 从洞洞板原型开始

**画面**

- 【洞洞板视频 00:58–01:48】洞洞板正反面、锂电池、升压模块、ESP32-S3、屏幕、SD 卡、RP2040 和 USB 声卡。
- 给每个模块加简洁引线标注，不要遮住洞洞板走线。
- 【洞洞板视频 00:00–00:28、01:54–04:03】透明外壳成品、频谱软件和实际播放画面。
- 【补拍】洞洞板原型与新 PCB 并排对比。

**口播**

> 这个项目并不是从 PCB 开始的。最早的版本，是我在洞洞板上一根线、一根线焊出来的。

> 它由锂电池和充电模块供电，其中一路 5V 升压给控制板，另一路 5V 升压经过滤波后单独给 USB 声卡供电。主控是 ESP32-S3，负责读取 SD 卡、解码 FLAC、驱动 LCD，同时以 USB Host 模式驱动声卡。旁边还预留了一块 RP2040，原本计划用来读取 CD 数据，再交给 ESP32-S3 播放。

> 当时使用的是创新科技 Sound Blaster PLAY! 3，在 USB Full Speed 模式下实现了 24-bit、96 kHz 播放。这个洞洞板版本证明了整个方案是可行的，也让我真正听到了播放器成功出声。

> 但原型的缺点同样明显：模块多、飞线密、体积大，供电和信号路径不直观；只要移动一根线，排错范围就可能扩大一圈。它适合验证想法，却不适合继续迭代，更不适合作为长期使用的成品。

> 所以这一次，我决定把已经验证成功的洞洞板方案重新整理，做成自己的 4 层 PCB。目标不是简单地“把飞线印到板上”，而是重新规划接口、供电、接地和数据路径，让它从能工作的原型，变成能够继续开发的平台。

## 03:01–04:14 PCB 设计：把飞线变成 4 层板

**画面**

- 【PCB 视频】EasyEDA 工程、原理图或 PCB 编辑界面。
- 放置 ESP32-S3、SD 卡、屏幕、I2S 和 USB 相关接口。
- 走线过程加速，重点位置恢复正常速度。
- 切换各铜层，最后进入 3D 预览。

**口播**

> 洞洞板版本让我知道哪些模块必须保留，也暴露了原先布线和供电的不足。我使用 EasyEDA 重新完成 PCB 编辑。第一步不是照着洞洞板抄线，而是先决定整块板的结构：ESP32-S3 放在哪里，SD 卡和屏幕接口朝哪个方向，USB 数据线怎样缩短，音频和数字部分怎样分开，以及所有外部接口焊好之后会不会互相挡住。

> 这是一块 4 层板。相比只追求“连通”，我更希望它在供电、接地和高速信号方面有更稳定的基础。布局确定之后，再按功能分区完成布线，并为 USB、SPI、I2S 和电源网络保留合适的路径。

> ESP32-S3 原生 USB 的 D- 和 D+ 使用 GPIO19、GPIO20；SD 卡单独使用 SPI2，运行频率是 20 MHz；屏幕使用 SPI3，像素时钟 40 MHz。这样 SD 卡和屏幕各用一套 SPI Host，避免重复初始化和总线争用。

> 走线结束以后，我先用 3D 预览检查元件方向、连接器位置和机械干涉。二维图上看起来没有问题的设计，放到 3D 里，经常马上就能看出接口朝反、器件打架或者空间不够。

**屏幕标注**

- `USB：GPIO19 / GPIO20`
- `SD：SPI2，20 MHz`
- `LCD：SPI3，40 MHz`
- `I2S：WS / BCK / DIN / MCLK`

## 07:08–08:44 固件开发：能亮屏还不算播放器

**画面**

- 【补拍/录屏】ESP-IDF 工程目录，依次高亮存储、解码、音频输出、显示、网络模块。
- 编译和串口日志。
- 屏幕显示 FAT32 挂载、扫描文件、开始播放。

**口播**

> 硬件焊好，只完成了一半。固件使用 ESP-IDF 5.5.1 开发，并按功能拆成存储、音乐库、解码、音频输出、显示、网页控制和 OTA 等模块。

> 开机后，屏幕会先显示启动状态，然后初始化 FAT32 SD 卡、递归扫描音乐文件，再启动播放器。MP3 使用软件解码；WAV 支持 PCM；FLAC 使用流式解码，并把工作缓冲和音频 ring buffer 放进 PSRAM，减少 SD 卡读取抖动带来的爆音。

> 音频内部使用 Q1.31 数据路径，24 位和 32 位 PCM 不会一开始就被截成 16 位。I2S 支持 8 到 96 kHz，并跟随文件切换采样率；FLAC 也按文件原始采样率输出，不做重采样。

> 显示部分使用原生 RGB565 驱动 ST7789。除了曲名和播放状态，底部还会实时显示频谱。中文和 UTF-8 文件名也做了显示和截断处理。

## 08:44–09:41 最难的部分：USB 声卡与热插拔

**画面**

- 【补拍】插入 CX31993，串口出现设备识别与启流日志。
- 耳机连接、屏幕输出设备名称变化。
- 拔出 USB 声卡，I2S 继续播放。
- 换接 Sound Blaster PLAY! 3。

**口播**

> 这个项目最难的部分，是让 ESP32-S3 不只是 USB 设备，而是作为 USB Host 去驱动声卡。CX31993 使用 USB Audio Class 2.0；Sound Blaster PLAY! 3 则是 UAC1，两者的枚举、描述符和播放格式都不完全一样。

> 系统启动时不会傻等 USB 声卡。没有 USB 设备就直接使用 I2S；发现可用的 USB 播放接口后，再按当前曲目的采样率启动音频流。USB 成功启流后成为首选输出，拔掉以后则自动停止并切回 I2S。

> CX31993 的 44.1 kHz 同步 OUT 端点还需要处理 44 帧和 45 帧交替的分数包调度。只有把这些看不见的时序细节处理好，最后听到的才不是断断续续的杂音。

## 09:41–10:34 真实踩坑与排错

**画面**

- 【补拍/历史素材】失败日志、黑屏、SD 挂载失败、示波器或万用表。
- README 中测试数据做成简洁表格动画。
- SD 读取从低速到 20 MHz 的日志快切。

**口播**

> 整个过程当然不是一次成功。SD 卡就遇到了很少见的兼容问题：卡片报告自己使用 SDHC 块寻址，实际读写命令却仍按字节地址解释。固件最后采用严格验证 FAT 启动扇区的方法，标准方式失败后再尝试兼容寻址；只有确认读到有效 BPB 才会切换，而且不会格式化卡片。

> 实测这张卡从 400 kHz 到 20 MHz 都能稳定读取，在 20 MHz 下大约达到 1133 KiB/s；40 MHz 初始化则会返回无效响应，所以最终选择 20 MHz 作为可靠运行档位。

> 还有屏幕和 SD 共用 SPI 资源、USB 声卡格式协商、FLAC 缓冲不足造成爆音，以及插拔设备后的状态恢复。做板之前，我以为最大的挑战是把线连起来；真正做完才发现，硬件、驱动和实际设备的边界条件，才是最耗时间的地方。

- 依次展示频响、噪声频谱、THD+N 图表；所有图使用同一纵轴范围。

- 结果揭晓后再把 A、B、C、D 标签替换成真实设备名。

**口播**

> 能正常播放，只能证明功能完成了。接下来才是开头留下的问题：它的输出到底怎么样？

> 这次参加对比的，是 I2S PCM5100A、CX31993、Sound Blaster PLAY! 3，以及保留 3.5 毫米耳机孔的 Sony Xperia 5 V。四台设备播放同一个无损测试文件，使用相同的采样率，输出接入同一台专业录音声卡的同一个输入通道。

> 正式比较之前，先用测试信号把四路输出匹配到相同电平，差异尽量控制在 0.1 dB 以内。因为只要其中一路稍微大一点，人耳往往就会把它误认为更清晰、更有力量。

> 第一项看频率响应。这里不比较谁的曲线“看起来更高级”，而是看可听频段内有没有明显滚降或起伏。第二项看空载和带负载时的底噪，第三项看固定输出电平下的失真与噪声，也就是 THD+N。

> 测量能告诉我们信号发生了什么，但不能替代听感。所以最后再做 ABX 盲测。软件会随机指定 X 是 A 还是 B，试听时不知道设备身份，只根据声音作答。单次猜对没有意义，要看多轮结果能不能明显高于随机概率。

> 【按实测结果录制，不要提前写结论】从曲线上看，〔填写频响结果〕；底噪方面，〔填写测试结果〕；THD+N 方面，〔填写测试结果〕。ABX 一共完成〔次数〕轮，正确〔次数〕轮，结果是〔能/不能〕稳定区分。

> 所以这次的结论不是“哪个一定更好听”，而是：在这套耳机、音量和测试条件下，〔填写最终结论〕。完整录音、原始图表和 ABX 记录，我会放在简介或后续文章里，方便大家自己判断。

**数据字幕模板**

```text
测试文件：〔文件名、位深、采样率〕
采集设备：〔专业声卡型号〕
负载：〔耳机型号/模拟负载与阻抗〕
输出电平：〔Vrms 或 dBV〕，匹配误差 ≤ 0.1 dB
频响：20 Hz–20 kHz，〔结果〕
底噪：〔测量带宽与 A-weighted/Unweighted〕，〔结果〕
THD+N：1 kHz，〔输出电平〕，〔结果〕
ABX：〔正确数〕/〔总轮数〕，p=〔数值〕
```

**测试注意**

- Xperia 5 V 和三个声卡的最大输出电压可能不同；比较音质时必须先匹配电平，不直接比较满音量。
- 测量线路输出时避免把专业声卡输入削波；比较耳机驱动力时另做带负载测试。
- 录音文件本身不能完整保留另一台 DAC 的模拟输出体验，发布时将它称为“回录样本”，不要称为无损还原。
- YouTube 会再次进行有损编码，频响和失真结论以原始测量文件为准。
- ABX 至少完成足够轮次并显示统计结果；如果不能稳定区分，也如实保留这个结论。

## 剪辑节奏与声音建议

- 开场前 15 秒内出现手机、播放器、三款声卡和测试图表，先提出冲突，再揭示“自己做”的主题。
- PCB 编辑段以 6–10 倍速为主，只在关键布局、DRC 和 3D 预览处回到正常速度。
- 焊接段保留直播的真实环境声，口播音量之下让烙铁接触、剪脚和万用表蜂鸣可听见。
- 技术信息不要一次堆满屏幕，每张字幕卡最多突出 3 个关键词。
- 成品演示尽量使用连续镜头；涉及版权音乐时，优先使用自制、已授权或免版税音源。
- 音频效果不能仅靠录制扬声器证明，可同步拍摄屏幕状态、输出设备变化和串口日志。
- 对比测试的四组图表必须使用相同坐标范围，避免视觉尺度误导。
- ABX 设备身份在测试完成前不要通过镜头、音量 UI 或切换声音泄露。

## 视频简介文案

手机已经这么强，为什么还要自己做一台随身音乐播放器？这期视频记录我把 ESP32-S3 无损播放器从洞洞板原型升级成 4 层 PCB 的完整过程：从 EasyEDA 布局布线、3D 预览、DRC、导出生产文件和打样，到手工焊接、首次通电、ESP-IDF 固件开发与实机调试。

播放器支持从 FAT32 SD 卡扫描并播放 MP3、PCM WAV 和 FLAC，使用 ST7789 显示曲目与实时频谱，支持 I2S、CX31993 UAC2 和 Sound Blaster PLAY! 3 UAC1 音频输出，并带有 USB 热插拔回退、网页控制和局域网 TCP OTA。

最后还会把 I2S PCM5100A、CX31993、Sound Blaster PLAY! 3 和 Sony Xperia 5 V 放在相同条件下进行回录测量与 ABX 盲听，用频响、底噪、THD+N 和盲测统计来回答它到底能不能打。

这不是严格的 PCB 教程，而是一份新手视角的完整开发和验证记录。希望它能给同样想把原型做成实体电路板的朋友一点参考。
